# RayTracerView: glTF リアルタイム PBVR プレビュー

引数なしの起動では、同梱 `samples/pbvr_cornell.gltf` を通常の
`GltfSceneRenderer` メインビューへ読み込む。PBVR lighting は既定で有効。
ファイルを指定した起動や Load 操作も同じ描画経路を使う。
シナリオ起動には既定モデルを読み込まず、既存の空シーンテストを維持する。

## 合成と蓄積

- 作業スレッドの独立 Vulkan device で放物面深度輸送とフォトンスプラットを実行。
- メインビューの orbit camera、FOV、縦横比を使用。最終受光画像は概ね画面辺長の
  1/8、最大辺 256。整数解像度による縦横比の差はシェーダーで補正。
- まず粗い輸送を表示し、カメラ静止 350 ms 後に独立 seed の高品質パスを逐次平均。
  カメラ・画面サイズ・モデル・有効状態の変更で世代を進め、旧結果を捨てる。
- 面光源の直接照明と発光は CPU G-buffer shading で世代ごとに計算して固定する。
  直接照明は 256 サンプル。`Indirect gain=0` で同じ直接照明を保ったまま
  PBVR の間接光だけを無効化できる（蓄積はリセットしない）。
  二次散乱以降の輸送と間接光集約は深度マップ/PBVR で行う。
- 既存の application scalar field（set 0 / binding 8）へ線形 HDR 照明・受光位置・
  法線を送り、専用 fragment shader が位置/法線を検査して補間する。
  対応する画素では照明全体を置換し、直接光・発光・環境光を二重加算しない。
  合成後に一度だけトーンマッピングし、sRGB swapchain に出力する。
- 粗い結果から精細パスへの切り替え中は同じカメラの表示を保持。
  カメラ移動時には旧照明を即座に無効にし、通常ラスタ照明へ戻る。

## 現時点の対象

静的・不透明・片面・無テクスチャ・metallic=0 の glTF と発光三角形の面光源。
テクスチャ、頂点色、morph、skin、アニメーション、金属、透過、両面、
KHR_lights_punctual は未対応と表示し、通常 glTF プレビューを維持する。
対応 glTF でも、曲面法線・低解像度受光・有限半径カーネル・放物面分割の
近似誤差は平均化しても残る。全 glTF の完全な PBR GI を実現するものではない。

同梱サンプルは既存の Cornell 実験の面・箱・光源を glTF にした合成モデル。
既定 orbit camera に開口部を向けるためモデル全体を回転し、原点へ移している。
従来の Cornell 専用パネルは独立した比較実験として残している。

## 検証結果（2026-10-07）

Release RayTracerView ビルド（専用 GLSL コンパイル込み）成功。
command_catalog（2 ステップ）、startup（4）、camera_control（5）、
`gltf_pbvr_preview.json`（17）の GUI シナリオすべて成功。
Vulkan validation error の出力なし。既存の APIENTRY マクロ再定義警告は残る。
引数なしの起動と、新規 imgui.ini での既定レイアウトも画像確認済み。

同じ面光源の直接照明を固定し、間接光 gain=0/1 を比較。
天井・箱の影の明るさと赤/緑の色移りを確認した。
160x90 の受光画像、精細パスの表示値は約 106〜120 ms/パス。
これは作業スレッドの計算時間であり、UI フレーム時間の計測ではない。
PBVR 4 パスと 16 パス以上（保存時の表示は 17 パス）の画像を保存。
カメラ距離変更後に蓄積世代が 7→9 と進み、新しい 4 パスを取得できた。
同等品質の CPU フォトンマップとの比較・誤差評価はこの実験では行っていない。
